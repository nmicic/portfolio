Executive summary

cunningham-chain-data is the publication surface for roots produced by the 2026 first-kind Cunningham-chain campaign. The git repository stays small: it contains a schema, manifest, thousand-row sample, and conversion script. Full cumulative snapshots are attached to versioned GitHub releases. The latest documented snapshot has 1,551,489 roots from CC10 through CC18 and is normalized as CSV. Keeping the dataset separate from the search engine makes release identity, citation, and downstream analysis clearer.

Problem and context

Campaign code and campaign data change at different rates. Storing a multi-million row aggregate in the source history would make the engine repository harder to clone and would blur which snapshot supports a result. This repository gives the data an explicit schema and release lifecycle of its own.

The documented bit range is 64–153, with the main campaign concentrated at 87–90 bits. The release is cumulative, not a delta from the earlier snapshot.

Boundaries

The repository publishes campaign output; it does not independently prove the mathematical or priority claims surrounding each root. Those methods and validation tools live in the search-engine repository. Full data is not present in a plain clone and must be obtained from the named release. The earlier raw snapshot remains a separate historical artifact.

Repository map and first use

git clone https://github.com/nmicic/cunningham-chain-data
python3 scripts/make_snapshot_csv.py --help

Read schema/README.md before consuming either sample or release data. Use the manifest to pin a snapshot in analysis work, and follow the release link in the source README for the full compressed CSV.
